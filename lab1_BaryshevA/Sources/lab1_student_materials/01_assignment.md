# Лабораторная работа № 1

## Markdown, LaTeX и воспроизводимый отчёт по прямому баллистическому расчёту

### 1. Цель работы

Освоить воспроизводимый цикл подготовки технического отчёта:

- реализовать расчёт на Python в виде запускаемого `uv`-проекта;
- исследовать работу реализации на самостоятельно выбранных баллистических решениях;
- представить формулы в LaTeX, результаты — таблицами и графиками, пояснения — в Markdown;
- собрать из Markdown итоговый PDF по сокращённому учебному профилю ГОСТ 7.32;
- подготовить работу к преподавательской проверке и последующему рецензированию.

### 2. Задание

Для своего, ранее выданного варианта курсовой работы программно реализуйте прямую баллистическую задачу с использованием `pyballistics`.

Программа должна рассчитывать баллистические решения для модели, назначенной в варианте, определять критерий варианта, учитывать все общие и индивидуальные ограничения и применять выбранную автором штрафную функцию.

После реализации проведите небольшое вычислительное исследование. Подберите набор баллистических решений и систему графиков, которые позволяют убедительно показать, что программа:

- корректно выполняет прямой расчёт;
- правильно вычисляет критерий;
- учитывает все ограничения варианта;
- правильно применяет штрафную функцию;
- предсказуемо обрабатывает допустимые, недопустимые и нерассчитываемые решения.

По результатам подготовьте отчёт в Markdown с LaTeX-формулами и рисунками, затем самостоятельно скомпилируйте его в PDF.

### 3. Функциональные требования

Реализация должна:

1. принимать данные ранее выданного варианта и параметры исследуемого баллистического решения;
2. вызывать назначенную вариантом модель `pyballistics`;
3. выполнять все расчёты, необходимые для проверки критерия и ограничений варианта;
4. возвращать не только итоговый признак допустимости, но и значения критерия, ограничений, штрафа, статусы расчёта и данные для построения графиков;
5. отличать нарушение ограничения от ошибки или нештатного завершения численного расчёта;
6. воспроизводимо формировать все рисунки отчёта при запуске `main.py`.

Для всех вариантов принять давление воспламенителя `p_ign_0 = 5 МПа`. Остальные исходные данные, определения величин, формулы критериев и ограничения необходимо найти в методическом пособии и корректно перенести в программу и отчёт.

Используется актуальная на начало выполнения работы версия `pyballistics`; фактическая версия фиксируется в `uv.lock` и выводится при запуске программы.

Архитектура программы, интерфейс расчётной функции, структура возвращаемых данных, параметризация баллистического решения, способ обработки температурных условий, состав вспомогательных функций и способ выбора исследуемых точек остаются на усмотрение автора.

Консультационные блокноты можно использовать как примеры работы с библиотекой и организации полного расчёта. Они не являются спецификацией интерфейса и не задают обязательную структуру решения.

### 4. Критерий и штрафная функция

Критерий определяется ранее выданным вариантом. Его формулу, обозначения, размерность и направление улучшения необходимо самостоятельно восстановить по методическому пособию, привести в отчёте и реализовать в коде.

Штрафную функцию студент выбирает самостоятельно и обосновывает. Единой обязательной формулы нет. Из отчёта и результатов должно быть понятно:

- как величина нарушения ограничения связана со штрафом;
- как совместно учитываются ограничения разных типов;
- как штраф изменяет критерий для недопустимого решения;
- как обрабатывается ошибка прямого расчёта;
- что исходный критерий и результат после применения штрафа не смешиваются.

Оптимизатор в этой лабораторной работе не используется. Штрафная функция исследуется только как часть вычисления и классификации отдельных баллистических решений.

### 5. План исследования и представление результатов

Число проверочных решений, способ их получения, набор графиков, координаты, таблицы и элементы инфографики студент выбирает самостоятельно.

Материалы должны образовывать связное доказательство корректности реализации: читатель должен иметь возможность проследить, какие свойства программы проверяются каждой точкой, таблицей или иллюстрацией и на основании каких чисел сделан вывод.

В отчёте необходимо объяснить:

- почему выбран именно такой набор баллистических решений;
- какие свойства реализации проверяет каждый элемент представления;
- достаточно ли полученных результатов для проверки всех ограничений, критерия и штрафа;
- какие случаи проведённое исследование не покрывает.

Обязательного перечня графиков и обязательной системы координат нет. График должен отвечать на сформулированный вопрос, иметь подписанные оси и единицы, показывать необходимые границы и оставаться понятным без обращения к программному коду.

### 6. Структура отчёта

Отчёт выполняется в файле `report.md`; формулы набираются в LaTeX, рисунки хранятся в каталоге `figures/`.

Обязательные блоки:

1. титульный лист;
2. краткое введение;
3. описание своего варианта, принятых обозначений и замысла проверки: какие свойства требуется проверить, какие графики и координаты для этого выбраны;
4. описание выбранной штрафной функции и основных решений реализации;
5. выбор баллистических решений, набор графиков и таблиц, краткий анализ результатов;
6. краткое заключение;
7. список использованных источников;
8. приложение с кодом.

Итоговый `report.pdf` компилируется студентом любым выбранным инструментом по требованиям `02_gost_profile.md`. Инструментарий сборки PDF в состав сдачи включать не требуется.

Отдельный `.py`-файл обязателен. Текст программы в приложении отчёта может полностью или частично дублировать его содержимое.

### 7. Состав сдачи и воспроизводимость

Отправляется один ZIP-архив. После распаковки структура должна иметь вид:

```text
lab1_<Фамилия>/
├── pyproject.toml
├── uv.lock
├── main.py
├── report.md
├── report.pdf
└── figures/
    └── ... все рисунки, используемые в report.md
```

Команды

```bash
uv sync --frozen
uv run python main.py
```

должны без ручных действий пересоздать все рисунки отчёта.

Пути внутри проекта должны быть относительными. Исходные данные, выбранные решения и параметры построения графиков должны находиться в коде или файлах проекта. Интерактивный ввод, ноутбук как единственная реализация и вручную исправленные после запуска изображения не допускаются.

В консоли при запуске необходимо вывести фактическую версию `pyballistics` и краткую информацию о рассчитанных баллистических решениях.

Для исправленной сдачи дополнительно требуется файл `changes.md` с перечнем замечаний и внесённых изменений.

### 8. Что не входит в работу

- поиск оптимального баллистического решения;
- выбор, сравнение или настройка оптимизаторов;
- разработка собственного решателя уравнений внутренней баллистики вместо применения заданной модели `pyballistics`;
- использование тестовой задачи из § 3.3 методического пособия как эталона проверки реализации для своего варианта.
