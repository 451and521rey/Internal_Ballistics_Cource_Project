# Сокращённый учебный профиль ГОСТ 7.32 для лабораторной работы № 1

Этот документ задаёт **полный проверяемый набор** требований к PDF в данной лабораторной работе. Требования полного ГОСТ 7.32-2017, которые здесь не перечислены, в рамках ЛР № 1 не проверяются.

Профиль основан на ГОСТ 7.32-2017 с поправками. Для однозначной автоматической и преподавательской проверки некоторые допустимые стандартом диапазоны ниже сужены до одного значения.

## 1. Состав отчёта

Обязательная последовательность:

1. титульный лист;
2. `ВВЕДЕНИЕ`;
3. нумерованные разделы основной части;
4. `ЗАКЛЮЧЕНИЕ`;
5. `СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ`;
6. `ПРИЛОЖЕНИЕ А`.

Для короткого лабораторного отчёта **не требуются** реферат, список исполнителей, содержание, перечень сокращений, терминов и определений. Все обозначения расшифровываются рядом с первой формулой или в локальной таблице обозначений.

## 2. Параметры страницы и текста

| Параметр | Требование этой работы |
|---|---|
| Формат | A4, печать/просмотр с одной стороны |
| Поля | левое 30 мм; правое 15 мм; верхнее 20 мм; нижнее 20 мм |
| Основной шрифт | Times New Roman, 14 pt; при его отсутствии — метрически совместимый шрифт с засечками |
| Цвет | чёрный |
| Межстрочный интервал | 1,5 |
| Выравнивание основного текста | по ширине |
| Абзацный отступ | 1,25 см во всём основном тексте |
| Интервалы до/после обычного абзаца | 0 pt |
| Переносы | в заголовках запрещены; в основном тексте допустимы |

Иностранные названия пакетов, команды и короткие имена объектов можно набирать моноширинным шрифтом. Листинг в приложении разрешено оформлять моноширинным шрифтом 9–10 pt с одинарным интервалом. Это учебная конкретизация для читаемости кода.

## 3. Нумерация страниц

- Нумерация сквозная арабскими цифрами, включая приложение.
- Титульный лист считается первой страницей, но цифра на нём не печатается.
- Номер печатается внизу по центру без слова «страница» и без точки.

## 4. Титульный лист

На титульном листе указываются:

- полное название образовательной организации и подразделения;
- название дисциплины;
- вид работы и её номер;
- тема;
- ФИО и группа студента;
- ФИО преподавателя;
- город и год.

ФИО на оригинальном Markdown и PDF разрешено и обязательно. Обезличенную копию для взаимного ревью готовит преподаватель.

## 5. Заголовки

Структурные заголовки `ВВЕДЕНИЕ`, `ЗАКЛЮЧЕНИЕ`, `СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ`, `ПРИЛОЖЕНИЕ А`:

- печатаются прописными полужирными буквами;
- располагаются по центру;
- не нумеруются;
- не заканчиваются точкой;
- начинаются с новой страницы.

Разделы основной части имеют номера `1`, `2`, …; подразделы — `1.1`, `1.2`, … без точки после последней цифры. Заголовок раздела или подраздела печатается полужирным, с абзацного отступа, без точки в конце. Каждый раздел начинается с новой страницы; подраздел может продолжаться на текущей странице.

После заголовка должен следовать текст: нельзя оставлять заголовок последней строкой страницы.

## 6. Формулы и обозначения

- Короткая формула может находиться в строке; значимая формула выносится на отдельную строку.
- Формулы, на которые есть ссылки, нумеруются арабскими цифрами в круглых скобках у правого края: `(1)`, `(2)`, … . Допускается нумерация в пределах раздела, например `(2.1)`, если она используется последовательно.
- Ссылка в тексте имеет вид: «… по формуле (3)».
- Пояснения символов приводятся сразу после формулы в порядке появления. Первая строка начинается словом `где` без двоеточия.
- Между числом и единицей ставится неразрывный пробел: `5 МПа`, `293,15 К`. В русском тексте десятичный разделитель — запятая; в исходном коде сохраняется точка.
- Один и тот же символ не должен обозначать разные величины. Единицы указываются для всех размерных величин.

LaTeX в `report.md` должен компилироваться без вставки формул как скриншотов.

## 7. Рисунки

- Перед каждым рисунком должна быть ссылка и объяснение, зачем он нужен.
- Рисунок размещается после первого упоминания либо на следующей странице.
- Нумерация сквозная: `Рисунок 1`, `Рисунок 2`, … .
- Подпись располагается под изображением по центру:

  `Рисунок 3 — Нормированные запасы по ограничениям`
- Точка в конце подписи не ставится.
- Все оси подписаны; после названия величины указана единица. Легенда расшифрована в тексте.
- Шрифт внутри рисунка после масштабирования должен оставаться читаемым. Рекомендуемый минимум — визуальный эквивалент 10 pt.
- Цвет не может быть единственным отличием линий: используйте также маркеры, тип линии или прямые подписи.
- В подписи или тексте указывается, если рисунок составлен по внешним данным. Графики, созданные `main.py`, считаются авторскими.

## 8. Таблицы

- На таблицу сначала ссылаются в тексте.
- Название размещается над таблицей слева без абзацного отступа:

  `Таблица 2 — Результаты проверки ограничений`
- Нумерация таблиц сквозная.
- В заголовках столбцов указываются единицы. Не повторяйте единицу в каждой ячейке.
- Для отсутствующего значения используется тире, а не пустая ячейка. Смысл тире при необходимости поясняется.
- При переносе таблицы повторяется строка заголовков и ставится помета `Продолжение таблицы 2`.

## 9. Числа, единицы и точность

- В одной колонке таблицы используется одинаковое число значащих разрядов, если более высокая точность не имеет специального смысла.
- График не должен создавать видимость точности, которой нет в расчёте.
- Давление в отчёте рекомендуется выводить в МПа, длину — в м и калибрах, ускорение — в `g` или м/с² с явным указанием.
- В тексте необходимо различать предел ограничения, вычисленное значение и нормированную величину нарушения.

## 10. Ссылки и список источников

В списке должно быть не менее трёх позиций:

1. методическое пособие по курсовой работе;
2. документация или репозиторий `pyballistics` с указанием версии;
3. ГОСТ 7.32-2017 либо источник его текста.

Источники располагаются в порядке первого упоминания и нумеруются арабскими цифрами с точкой. Ссылки в тексте — в квадратных скобках: `[1]`, `[2, с. 67]`.

Для сетевого источника указываются название, URL и дата обращения. Ссылка должна вести на конкретный использованный материал, а не на поисковую выдачу.

## 11. Приложение с кодом

Приложение начинается с новой страницы. Сверху по центру:

```text
ПРИЛОЖЕНИЕ А
(обязательное)

Текст программы прямого расчёта
```

Код в приложении должен соответствовать сдаваемому `main.py`. Допускается включить полный текст или существенную часть с явным указанием: «Полный исполняемый файл `main.py` входит в электронное приложение к отчёту». Наличие отдельного `main.py` обязательно независимо от содержимого приложения.

## 12. Что проверяется только преподавателем

Преподаватель проверяет PDF: поля, шрифты, интервалы, нумерацию, заголовки, подписи, переносы, список источников и приложение. Студенческие рецензенты получают Markdown и рисунки и не выставляют замечания по PDF-вёрстке.

## 13. Контрольный список перед сдачей

- [ ] Титульный лист учтён в нумерации, но номер на нём скрыт.
- [ ] Все обязательные структурные элементы присутствуют и начинаются с новой страницы.
- [ ] Формулы набраны, а не вставлены картинками.
- [ ] На каждую формулу, рисунок и таблицу есть ссылка из текста.
- [ ] Подписи и единицы однозначны.
- [ ] Все рисунки читаемы при масштабе 100 %.
- [ ] Список источников связан со ссылками в тексте.
- [ ] Приложение соответствует фактическому коду.
- [ ] PDF открывается и не содержит обрезанных элементов или пустых страниц.
