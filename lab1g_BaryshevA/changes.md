# Перечень исправлений по замечаниям преподавателя

Все пути ниже указаны относительно корня проекта
`Internal_Ballistics_Cource_Project/`.

## 1. Алгоритм определения длины ствола

- В `lab1g_BaryshevA/main.py:178-429` функция `run_ballistics_safe`
  переведена на два взаимоисключающих режима останова. Базовый режим при
  +20 °C использует целевую скорость `v_p = 650` м/с и одновременно сохраняет
  защитные ограничения по координате, давлению и числу шагов. Режим с
  фиксированной координатой применяется только к последующим температурным
  расчётам.
- В `lab1g_BaryshevA/main.py:353-424` проверяется фактический `stop_reason`.
  При недостижении 650 м/с сохраняются траектория, конечная координата и
  диагностический объём; сообщение явно запрещает использовать этот объём как
  критерий. Такому исходу назначается отдельный статус «цель не достигнута»;
  вычислительная ошибка по-прежнему имеет статус «ошибка», а рассчитанное
  нарушение ограничения не меняет статус прямого расчёта.
- В `lab1g_BaryshevA/main.py:546-679` функция
  `evaluate_ballistic_solution` сначала выполняет базовый расчёт при 293,15 К,
  фиксирует полученную длину `l_m`, вычисляет по ней `W_pm` и только затем
  запускает расчёты при 223,15 К и 323,15 К до одного и того же среза.
- В `lab1g_BaryshevA/main.py:737-753` консольный вывод отдельно показывает
  диагностические координату, скорость, объём и причину останова; критерий,
  штраф и допустимость остаются неопределёнными.
- Описание алгоритма приведено в разделе 1.2
  `lab1g_BaryshevA/report.md:118-155`; пересчитанные длины и сценарий
  недостижения скорости — в таблице 3 и разделе 2.3
  `lab1g_BaryshevA/report.md:217-229,300-314`.

Контрольные результаты: для допустимого сценария
`l_m = 5,081797220` м; для недопустимого — `l_m = 1,453986347` м. При
массе заряда 1,200 кг целевая скорость не достигается: `stop_reason = x_p`,
`x_final = 5,100000000` м, `v_final = 604,992591` м/с,
`W_diag = 0,03409755718` м³; значение `W_diag` не назначается критерием.

## 4. Близкая пара и чувствительность штрафа

- В `lab1g_BaryshevA/main.py` добавлены две воспроизводимые проверочные точки
  `boundary_a` и `boundary_b` по разные стороны ограничения
  $p_{mz,+50}\le110$ МПа. В обеих точках используются порох 8/1 тр,
  $W_0=0{,}006500$ м³ и одинаковые температуры, модель, численный шаг и
  ограничения; меняется только масса заряда с 2,312 до 2,313 кг, то есть на
  1 г.
- В точке А получено $p_{mz,+50}=109{,}880236$ МПа. Все ограничения выполнены,
  нормированные нарушения и штраф равны нулю. В точке Б получено
  $p_{mz,+50}=110{,}033383$ МПа, единственное нарушение равно
  $r_{pz,+50}=0{,}000303481$, а штраф —
  $P=1{,}712659\cdot10^{-7}$ м³. Тем самым показано плавное появление
  измеримого квадратичного штрафа при малом переходе через границу.
- Обе точки выводятся в консоль после трёх исходных сценариев и внесены в
  таблицы 2—5 `lab1g_BaryshevA/report.md`. Таблица 5 отдельно показывает
  изменение массы, знак отклонения давления от 110 МПа, нормированное
  нарушение и вклад штрафа.
- В повторном наборе намеренно не показано срабатывание ограничений по холодной
  дульной скорости и длине ствола. В исследуемом локальном сечении пространства
  параметров эти ограничения не являются активными: для точек А и Б получены
  $v_{pm,-50}=623{,}208$ и 623,206 м/с при минимуме 570 м/с, а длины равны
  2,051575 и 2,049563 м при пределе 5,10 м. Защитные пределы не достигаются;
  по заданию требовалась прямая проверка выбранных решений, поэтому полная
  оптимизация для искусственного достижения этих границ не проводилась.

## 5. Метаданные, структура и причины останова

- Из `lab1g_BaryshevA/pyproject.toml` удалена строка
  `readme = "README.md"`, то есть метаданные больше не содержат ссылки на файл
  описания, который может отсутствовать в составе сдаваемого архива.
- Все изменяемые исходные файлы, отчёт и автоматически создаваемые рисунки
  находятся внутри общего каталога `lab1g_BaryshevA/`. При формировании архива
  этот единый корневой каталог переименовывается в `lab1_BaryshevA/`; пути к
  рисункам в коде и отчёте остаются относительными.
- Итоговая консольная сводка расширена: для каждого успешно рассчитанного
  решения теперь явно выводятся причины останова базового, холодного и горячего
  запусков (`stop_reason[normal] = v_p`, `stop_reason[cold] = x_p`,
  `stop_reason[hot] = x_p`). Диагностический сценарий по-прежнему отдельно
  показывает свою причину защитного останова.
